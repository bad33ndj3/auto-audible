# Auto Audible Wiki

This wiki captures **external/runtime knowledge** discovered while repairing the wrapper, with sources.

It is intended as a handover artifact for future AI agents.

## 1) Upstream CLI behavior that changed

### Finding
`audible-cli` no longer exposes a top-level `decrypt` command in the current installed version.

### Evidence
- Local runtime check: `audible --help` (current install on host)
- Installed command list includes `activation-bytes`, `download`, `library`, `manage`, etc.

### Impact on this repo
- Wrapper must not rely on `audible decrypt`.
- Conversion must be handled via `ffmpeg`.

### Source
- Upstream project: `https://github.com/mkb79/audible-cli`

---

## 2) Library export format assumptions

### Finding
`audible library export` supports JSON output and it is stable enough for ASIN parsing.

### Evidence
- Local command: `audible library export --format json --output <file>`
- Observed JSON records include fields like `asin`, `title`, and metadata.

### Impact on this repo
- Prefer JSON export + JSON parsing over brittle TSV parsing.

### Source
- Local command help: `audible library export -h`
- Upstream project: `https://github.com/mkb79/audible-cli`

---

## 3) Detecting whether Audible setup exists

### Finding
`audible manage profile list` can be used to detect whether quickstart/auth setup exists.

### Evidence
- Local command: `audible manage profile list`
- If profiles exist, wrapper can proceed non-interactively.

### Impact on this repo
- Wrapper should verify setup before `sync`/`download`/`convert`/`status`.
- Interactive flows may offer to run `audible quickstart`.

### Source
- Local command help: `audible manage profile -h`
- Upstream project: `https://github.com/mkb79/audible-cli`

## 4) Optional auth password behavior

### Finding
Auth-file password is optional from wrapper perspective:
- unencrypted auth files work without `--password`
- encrypted auth files can still be used by passing password

### Evidence
- Local runtime verification with configured profile and no wrapper password.

### Impact on this repo
- `--password` must remain optional.

### Source
- Local runtime behavior using installed `audible-cli`
- Upstream project: `https://github.com/mkb79/audible-cli`

## 5) AAX conversion path (.aax -> .m4b)

### Finding
`.aax` conversion works through ffmpeg using Audible activation bytes.

### Evidence
- Local ffmpeg demuxer options include `-activation_bytes` for Audible AAX.

### Impact on this repo
- For `.aax`: retrieve activation bytes via `audible activation-bytes`, then convert with ffmpeg.

### Source
- Local command in container:
  - `ffmpeg -hide_banner -h demuxer=mov`
- Upstream project: `https://github.com/mkb79/audible-cli`

---

## 6) AAXC conversion path (.aaxc -> .m4b)

### Finding
`.aaxc` conversion is possible directly in ffmpeg when passing key+iv from voucher:
- `-audible_key <hex>`
- `-audible_iv <hex>`

### Evidence
- ffmpeg mov demuxer options show both `audible_key` and `audible_iv`.
- Voucher files generated by `audible-cli` contain:
  - `content_license.license_response.key`
  - `content_license.license_response.iv`
- End-to-end conversion succeeded in Docker using those values.

### Impact on this repo
- `.aaxc` should be converted, not just reported as pending.
- Conversion requires matching `.voucher` file.

### Source
- Local command in container:
  - `ffmpeg -hide_banner -h demuxer=mov`
- Installed audible-cli source:
  - `.../site-packages/audible_cli/cmds/cmd_download.py` (voucher handling and `download_aaxc`)
- Upstream project: `https://github.com/mkb79/audible-cli`

## 7) Media status state model used by wrapper

### States
- `ready`
- `needs_convert_aax`
- `needs_convert_aaxc`
- `tracked_no_media`
- `not_downloaded`

### Why these states
They separate destination-scoped library bookkeeping (`<media-dir>/.auto-audible.json`) from actual on-disk media readiness.
